- 2026-10-28 P6: Audio = chirp-keyed bursts, 17.5-19.0 kHz, `shared/audiocodec.ts` (pure maths, shared by emitter and receiver). Burst = 40 ms slow up-chirp preamble + 32 bits (window mod 256, 16-bit server code, CRC-8) as 20 ms up/down chirps = 680 ms, one burst per QR window, amplitude 0.25 default with a volume slider. Receiver: mic with echoCancellation/noiseSuppression/autoGainControl off -> AudioWorklet tap (ScriptProcessor fallback) -> complex baseband (mix to 18.25 kHz, integrate-and-dump to ~3 kHz) -> matched filter preamble -> up/down bit correlators -> CRC. Works at any sample rate (tested 32/44.1/48/96 kHz). The 16-bit code is HMAC(secret, "audio|sid|window"), NOT derived from the QR token, so a relayed QR image does not reveal it. Server accepts a heard code if it matches a window within `AUDIO_MAX_AGE_MS` (8 s) + grace; heard = no change, not heard = flag `AUDIO_UNAVAILABLE` and -0.1 (stays VERIFIED if the rest is clean, never rejects), CRC-valid but wrong/too-old = `AUDIO_MISMATCH` (REVIEW flag: this can only be a replay or relay). Only applied when the session has `audio_mode=burst` (professor ticks "ultrasound beacon" at session creation; default on); sessions with audio off score exactly as in P5. `/sessions/{id}/audio-plan` is now readable by the professor (owner) and by rostered students (not professor-only as in the stub list). `/trial/audio-log` stores numbers only (preamble correlation peak, frames, sample rate, mic settings, result) and only when `GK_TRIAL_MODE=1`; otherwise 204 and dropped. Professor emitter needs one click (browser autoplay policy). Mic permission is a second prompt for students on first check-in of a beacon session. Cut per list: second frequency slot, lower-band tier (not built), FEC beyond CRC; the "per-phone self-test" is delivered as telemetry (mic settings actually applied, sample rate, worklet yes/no, best correlation seen) rather than a separate calibration screen, because a real test needs a beacon playing.

## P9
- Single backend worker; the live-feed hub stays in-process. Redis is used for nonces and rate counters only. A multi-worker hub (Redis pub/sub) is deferred: a pilot class is far below one worker's capacity, and a wrong cross-worker feed would be worse than a limit.
- Rate limits are per identifier/user, never per IP alone (campus NAT): login 10 failures/10 min per identifier (success clears), 200 failures/10 min per IP; challenge 20/min and check-in 60/min per student (a retrying scan is about 24/min). Redis outage never blocks users.
- Uniform error envelope now also covers 404, 405 and unhandled 500s (`INTERNAL`); every response carries `x-request-id` equal to the envelope's id.
- Prod refuses to start without a real secret, photo key, Redis, Postgres, `FACE_MODE=required`, rate limiting on. `/docs` and the schema are off in prod. Same-origin deploy, so CORS is off unless `GK_CORS_ORIGINS` is set.
- Retention: nightly clears check-in face vectors after 30 days, audio telemetry after 90, spent challenges after 1 day. Term end deletes templates (vector + photo) for a course's roster on demand. Records, statuses and audit log are kept.
- Audit additions: login success/failure, course create/update, retention runs, CLI user creation.
- Deploy: Docker compose with Caddy (auto HTTPS), Postgres 16, Redis 7; two hostnames (student, professor). Backups stay in India.
