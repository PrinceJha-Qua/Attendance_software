Scope: `docs/V1_SCOPE_AND_PHASES.md` P8 and section 3 (calculator). Builder's checks: `backend/tests/test_calculator.py` (table-driven, 16 cases) and `tests/test_dashboard.py` (3 tests).

## Calculator cases (exact numbers; table-driven, include your own random property test)
1. Worked examples: A=27,T=34,r=75 -> 79.4%, safe, `skip_now`=2. A=20,T=30 -> 66.7%, below, `need_in_a_row`=10.
2. Edges: T=0 -> pct null, status `none`; exactly on the line (3/4) -> borderline, skip_now 0; 26/34 -> borderline 0; 28/34 -> safe 3; 10/10 -> 100%, safe 3; 0/5 -> need 15; r=100 and below -> `need_in_a_row` null; r=100 at 10/10 -> borderline 0; r=0 -> safe.
3. With planned total S: `can_skip_until_end = max(0, (S-T) - max(0, ceil(rS)-A))`; A=20,T=24,S=40 -> 6; unreachable case (A=10,T=30,S=40) -> `reachable` false and the student app says reaching 75% is no longer possible; S < T ignored (null); T=0, S=40 -> 10.
4. Property test: for random A<=T, r in {50..100}: if status safe/borderline with skip_now=k, then missing exactly k more classes (attending none of them) leaves A/(T+k) >= r and missing k+1 drops below r; for below with need=n, attending n in a row gives (A+n)/(T+n) >= r and n-1 does not.
5. Excused: `course.excused_counts` true counts an `excused` record as attended, false does not (PATCH the course, numbers change at once).

## API cases
6. Dashboard numbers equal a recomputation from the DB and from the professor's CSV exports (sum the exports of all closed sessions); T counts only CLOSED sessions and only the student's own records (a student added to the roster after 3 closed sessions has T=0 until the next close).
7. Course history: ordered newest first, `can_dispute` true only for `absent` without a dispute, `source=checkin` hides the internal note (students never see `unreviewed: FLAGS` text or any flag names), manual/resolved rows show their source. Student not on roster / unknown course -> 404; professor token -> 403; no token -> 401.
8. Dispute create: `absent` own record -> 201 {id,status:open}; present/excused record -> 409 `NOT_DISPUTABLE`; another student's record id or unknown id -> 404 `RECORD_NOT_FOUND` (identical response for both); second dispute on the same record -> 409 `DISPUTE_EXISTS`, including after it was decided; note shorter than 3 or longer than 500 -> 422; 20 simultaneous creates -> report how many rows exist (known race, see parking lot: expect 1, record if more).
9. Decide: only the course's professor (others 404); accept -> record `present`, source `resolved`, note `dispute accepted[: note]`, dashboard A+1 immediately; reject -> record unchanged, student sees `decided_note`; repeat same decision -> 200 same body; opposite decision -> 409 `ALREADY_DECIDED`; invalid decision -> 422; `audit_log` has `dispute.accepted|rejected` with the professor id.
10. Inbox: `status=open` only open ones, `all` includes decided; each item shows student name/roll no, date, record source/note (to see whether the professor themself marked it), student note; other professors -> 404. `GET /students/me/disputes` shows only own, newest first.
11. Report: one row per roster student with the same numbers the student sees, `unreviewed_flags` = records with source `checkin` and note starting `unreviewed`, `open_disputes` counts, `sessions_conducted`, `open_session_id` (null if none). Report and the student's dashboard agree for every student in a 30-student seeded course after 10 closed sessions with mixed outcomes.
12. A not-here spot-check verdict (P7) followed by the student's dispute and the professor's accept reverses the record and the audit trail shows both steps.
