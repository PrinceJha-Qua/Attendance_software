# Phase 9 acceptance (hardening, privacy, deploy) — for AGY

Setup: backend dev server, seeded DB. Run `uv run pytest -q` first (builder suite: 142 passing, includes tests/test_hardening.py).

## A. Error envelope and headers
1. Unknown path, wrong method, malformed JSON body, missing field: every one returns `{error:{code,message,request_id}}`; `request_id` equals the `x-request-id` header.
2. Force a server error (e.g. monkeypatch a handler to raise): 500 `INTERNAL`, no stack trace or file names in the body.
3. All responses have `x-content-type-options: nosniff`, `cache-control: no-store`, a restrictive CSP. With `GK_ENV=prod` also HSTS, and `/docs` and `/api/v1/openapi.json` are 404.

## B. Rate limits
4. 10 wrong passwords for one identifier then the 11th (even correct) → 429 `RATE_LIMITED`. Another identifier from the same client is unaffected. A success before the limit clears the count.
5. 21st challenge request in a minute by one student → 429; a different student is unaffected.
6. 61st check-in post in a minute by one student → 429. Normal use (retry every 2.5 s) never reaches it.
7. With `GK_RATE_LIMIT=off` in dev, none of the above limit.

## C. Prod guards (run `python -c "import app.config"` with env)
8. `GK_ENV=prod` fails when each is missing/unsafe: `GK_SECRET_KEY`, `GK_PHOTO_KEY`, `GK_REDIS_URL`, a SQLite `GK_DATABASE_URL`, `GK_FACE_MODE=off`, `GK_RATE_LIMIT=off`. `scripts/seed.py` refuses under prod.

## D. Retention and audit
9. `scripts/retention.py`: a check-in older than 30 days loses `face_vector` but keeps status/score; template untouched. Audit row `retention.daily`.
10. `scripts/retention.py --term-end <course>`: all roster students' templates (vector + photo) gone; `/students/me/enrollment` shows `none`; attendance records intact; audit row written. Students on other courses only are untouched.
11. Audit log has rows for: login ok/fail, course create/update, roster import, enroll confirm/reject, photo view, session lifecycle, spot check, resolve, manual, export, dispute create/decide, consent, enroll, face-data delete.
12. Logs (`GK_LOG_JSON=1`): one JSON line per request with rid/method/path/status/ms; no query string, no Authorization header, no request body, no WS token.

## E. Deploy (needs a VM; do as a dry run, user will supply)
13. Follow `docs/DEPLOY.md` §2–3 on a clean box (or local Docker). Report every step that needed fixing.
14. After restart of the backend container: students can still log in; open sessions' live feed reconnects with resync.
15. `deploy/backup.sh` produces a dump; restore into an empty DB and log in.
16. Run the P1–P8 suites against the Postgres stack (`GK_DATABASE_URL=postgresql://…`, dev env) and report any failure (known risk: only SQLite has been exercised).
