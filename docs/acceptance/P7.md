# Phase 7 acceptance: Professor live console
Scope: `docs/V1_SCOPE_AND_PHASES.md` P7. Builder's own checks: `backend/tests/test_live_console.py` (8 tests) plus all earlier suites. Dev: `GK_FACE_MODE` default (required) unless you are re-running P1-P4 fixtures.

## What changed since P6 (update fixtures)
- `POST /sessions` returns **409 `OPEN_SESSION_EXISTS`** if the course already has a created/live/paused session. Your P3/P4 fixtures that create two sessions in one course must close the first (or use two courses).
- `POST /sessions/{id}/close`, `/attendance`, `/attention`, `/spotcheck/suggestions`, `/spotcheck/{student_id}`, `/attendance/{student_id}/resolve`, `/attendance/manual`, `/export` are real (no longer 501).
- WebSocket `/api/v1/ws/sessions/{id}` no longer closes with 1013. Missing/invalid token or a student token -> closed with 4401 before accept; another professor's session -> 4404.

## API cases
**Close and records**
1. `close` on live or paused: status `closed`, `closed_at` set, exactly one `attendance_records` row per rostered student: checked in (VERIFIED or REVIEW) -> `present`/source `checkin` (REVIEW rows carry note `unreviewed: <flags>`), no check-in -> `absent`/source `default`. Second `close` -> 200, same state, no extra rows, no duplicate audit spam beyond one `session.closed`. `close` on `created` -> 409 `INVALID_STATE`. Another professor -> 404, student -> 403. 20 simultaneous `close` calls -> one set of rows, no 500.
2. Decisions made before close (resolve, manual, spot-check) survive close unchanged (sources `resolved`/`manual`).
3. After close: `tokens` and check-ins refuse (`SESSION_NOT_LIVE` / `SESSION_NOT_ACTIVE`); `/sessions/active` no longer lists it; a new session can be created for the course.

**Live list**
4. `GET /attendance`: `{session, summary, students[]}`; every roster student once; `display` in checked_in|review|not_here|present|absent|excused; `final` is what close would write; counts in `summary` add up to roster size. Not visible to other professors (404) or students (403). No photos or face vectors appear anywhere in this payload.

**Attention Panel**
5. Flagged: a REVIEW check-in shows as `kind=flagged` with plain-language `reasons` (no words like cheating/fraud), `photo_url` (null when the student has no stored photo), ranked above overdue; collisions name the other student ("Same face as ..."); look-alike mismatches name the enrolled classmate ("Face resembles ...").
6. Overdue: inside `ATTENTION_GRACE_S` (180 s) nobody is overdue; after it every roster student with no check-in and no decision is `overdue`, ordered by past absence rate in the course (closed sessions' `absent` records), then name. `k` caps the list (default 5, 1-20 enforced -> 422), `total_open` is the uncapped count.
7. Cards leave the panel after a spot-check (any result) or a resolve/manual. `unsure` leaves the student in the review queue (display `review`) and records nothing.
8. Suggestions: same list plus up to 2 random VERIFIED students with `kind=audit`; a `not_seen` on one increments `summary.audit_not_seen` (this is the live false-accept measurement); `seen` on a VERIFIED student is harmless.
9. Spot-check rules: `seen` -> present, `not_seen` -> absent, both source `resolved` with a default note; `unsure` -> no record; invalid result -> 422; student not on roster -> 404 `NOT_ON_ROSTER`; session closed or not started -> 409. Repeated verdicts: the latest wins; every verdict is in `audit_log`.
10. Photo security: `photo_url` from the panel works for the owning professor once for 5 min (existing P2 rules), 403 for another professor, expired/tampered signature rejected, each fetch writes `photo.viewed`. Panel/ws payloads contain no photo for students who are not on the panel.

**Resolve / manual / export**
11. `resolve` {present|absent, note?}: upserts the record (source `resolved`), idempotent, works live and after close (used later by disputes), 409 only before start; other values -> 422. `manual` {student_id, reason (3-300 chars, required), status=present}: 201, source `manual`, reason stored as the note, audited; unknown/unrostered student -> 404; missing/short reason -> 422.
12. `export?format=csv`: header `roll_no,name,status,source,checkin_status,score,flags,note`; one row per roster student; for a closed session the file equals the `attendance_records` + `checkins` tables exactly; values starting with `= + - @` are prefixed with `'`; `format=xlsx` -> 422; other professors -> 404; `X-Session-Status` header present.

**WebSocket**
13. Auth: no token / garbage / student token / other professor -> closed, never accepted. Owner: first frame `hello` (`seq`, `resync`, current stats).
14. Events within 500 ms of the cause (measure from the check-in response to the frame): `checkin.created`, `checkin.updated` (collision pulls the earlier student into REVIEW), `attention.raised` (carries `photo_url` for students with a stored photo), `attention.cleared`, `session.state`; `stats.tick` every 1 s (+-200 ms) with checked_in, review, roster, rate_per_s, p50_ms, p95_ms; `ping` -> `pong`.
15. Reconnect: reconnect with `since_seq=<last seq>` -> only missed events, in order, none duplicated; `since_seq` larger than the server's current seq (restart) or older than the 500-event ring -> `hello.data.resync=true` and no backlog. Burst: 240 check-ins in 5 s with 3 connected dashboards: every dashboard sees 240 `checkin.created`, in seq order, p95 delivery <= 250 ms (B-PERF-04); a dashboard that disconnects mid-burst and reconnects recovers via replay or resync.
16. A closed or deleted client does not leak: after 100 connect/disconnect cycles the hub has no stale subscribers (memory flat).

## UI cases (prof-console, Chromium; second window for the projector route)
17. Session page: Start -> Pause/Resume/Close buttons per state; Close asks for confirmation; after close the buttons go away and the roster shows final statuses; live dot is green while the WS is connected, red while reconnecting (kill the backend for 10 s and bring it back: the page recovers without a reload and counts are correct).
18. Stats row updates within 1 s without polling spikes; the checked-in count matches `/attendance`.
19. Attention Panel: a flagged student's card (photo, name, roll no, reasons, three buttons) appears within 500 ms of the student's check-in (measure phone-submit to card visible); Seen/Not here/Unsure remove the card and update the roster row; a student without a photo shows "No photo". Photos are not re-downloaded on every list refresh (network log: one `/students/{id}/photo` request per student per card); the blob URL is revoked when the card goes.
20. **Privacy:** `/project/:id` never shows names, photos or counts (view-source and network: no calls to `/attention`, `/attendance`, `/ws`); the private page carries the warning to keep it off the projector. Mirror-risk check: opening `/session/:id` in the projector window is the professor's mistake, so the warning text must be visible there.
21. Review queue and "Add by hand": Present/Absent buttons resolve; "Add by hand" prompts for a reason (empty cancels) and the row shows "added by hand" with the reason.
22. Export CSV downloads a file named `attendance_<id>.csv` whose rows match the screen.
23. CourseDetail: creating a session while one is open shows the "already has an open session" message.
24. Bundle: prof-console main 206.9 KB (68 KB gzip), report real transfer size.
