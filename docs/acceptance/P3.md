# Phase 3 acceptance: Session lifecycle + Projection screen
Scope: `docs/V1_SCOPE_AND_PHASES.md` P3. Dev password `gatekeeper-dev`. Backend `uv run uvicorn app.main:app`; professor app `npm run dev` in `prof-console` (port 5174).

## Real endpoints in P3 (5; `close` stays a stub until P7)
`POST /sessions`, `GET /sessions/{id}`, `POST /sessions/{id}/start|pause|resume`, `GET /sessions/{id}/tokens?from=&count=`.

## API cases
**Create / read**
1. `POST /sessions {course_id, step_ms?, audio_mode?}` -> 201 status `created`, defaults step_ms=1500, audio_mode=off. step_ms must be 1000..10000 (else 422); audio_mode only `off|burst`; unknown or other professor's course -> 404 `COURSE_NOT_FOUND`; student token -> 403. Response includes `roster_count`; `checked_in_count` is 0 until P4.
2. `GET /sessions/{id}`: owner only; another professor or unknown id -> 404 `SESSION_NOT_FOUND`. Two sessions for the same course may coexist (rule deferred to P7).
3. The per-session secret never appears in any response (search every response body).

**State machine** (`created -> live <-> paused`; `closed` only via P7)
4. start: created->live sets `started_at`; any other state -> 409 `INVALID_STATE`. pause: live->paused only. resume: paused->live only (does not change `started_at`). Each transition writes an `audit_log` row. Repeating a transition -> 409.
5. Auth matrix still holds: no token 401, student 403 on all these routes; `close` still returns 501.

**Token batches**
6. Only when `live` (created/paused -> 409 `SESSION_NOT_LIVE`). Default response: tokens from the current window through 60 s ahead (about 41 tokens at step 1500), at most 100. Shape `{step_ms, server_ms, tokens:[{window, payload}]}`; consecutive windows, payload format `gk1:{session_id}:{window}:{16 chars}`.
7. `from` older than current window minus 1 -> 422 `WINDOW_TOO_OLD`; beyond 60 s ahead -> 422 `TOO_FAR_AHEAD`; `count` 1..100 (0 or 101 -> 422); `count=3` returns exactly 3. Non-owner professor -> 404.
8. Cross-check with the shared spec: every returned payload matches `shared/TOKEN_SPEC.md` computed independently with the session secret (read from the DB in the test); each token verifies `ok` at its own window and `expired` once older than the grace; a token from session A fails verification against session B (`invalid`).
9. Token for the current window changes exactly at window boundaries (`floor(server_ms / step_ms)`); server_ms is within 2 s of test clock.

**Load**
10. 240 concurrent `GET /tokens` (simulating many professor tabs, or repeated polling) and 240 `GET /sessions/{id}`: report p50/p95/p99, no 5xx. Target p99 <= 400 ms.
11. Hammer start/pause/resume from two clients concurrently: final state is one of the valid states; no 500s.

## UI cases (Chromium + WebKit; real or virtual display)
**Session page** (`/session/:id`, from course page buttons 1.5s / 3s / 5s)
12. Create from the course page lands on the session page; Start / Pause / Resume buttons show only in the right states; status refreshes every 3 s; "Open projection screen" opens `/project/:id` in a new tab only when live or paused.

**Projection** (`/project/:id`; must work in a separate window of the same signed-in browser)
13. Shows only: the QR, a thin countdown bar at the bottom, and status text. No student data, names or photos anywhere in the DOM. `Waiting to start…` before start, `Paused` while paused (no QR drawn), `Session closed` after P7.
14. While live, the QR changes every `step_ms` (+/- 100 ms jitter). Decode the canvas with an independent decoder (e.g. jsQR/zxing) repeatedly for 60 s: every decode returns a payload whose window equals `floor((server_ms_at_that_moment) / step_ms)` with the browser clock deliberately skewed by +/-5 s (client uses server offset).
15. Offline resilience: block network for 20 s -> QR keeps rotating from prefetched tokens (no blank frame); after 60 s offline it shows "Reconnecting…" and recovers on reconnect without reload. Refill happens when under 30 s of tokens remain.
16. Size slider (30-100%) changes QR size without breaking decode; F key toggles fullscreen; controls bar hides after 3 s of no mouse movement. QR is black on white with a 4-module quiet zone at all sizes. QR is version 5 (37x37 modules) for the 64-char payload (note for the room trials).
17. Resize the window while live: QR redraws crisp (integer pixels per module, no blur). Wake-lock requested when supported (no error when unsupported).
18. Open 3 projection tabs for the same session: all stay in sync (same window at same time).
